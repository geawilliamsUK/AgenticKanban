# Status

Last updated 2026-10-23. The design is [DESIGN.md](DESIGN.md); milestones are its section 19.

## Done

**Milestone 1, human-only multi-project kanban.** Workspace of four crates (`ak-core`, `ak-store`, `ak-runtime`, `ak-app`), 44 tests, clippy clean. Projects register from `~/.agentic-kanban/config.toml`, one SQLite store per project, event log, notification routing, inbox, board with drag and drop, ticket panel with editing, comments with replies, freeze and unfreeze, `@mention` completion and highlighting.

Verified by the user in the running app: creating, opening, editing and moving tickets, commenting, mentions.

**Milestone 2, slice 1: agent definitions and editor.** Definition files in Claude Code's subagent format under `~/.agentic-kanban/projects/<id>/agents/<handle>/` (`agent.md` plus `memory.md`), parsed and rendered by `ak-core` with unknown frontmatter keys preserved. An `agents` table caches each file plus runtime state. The runtime reconciles rows from files on project open, on save, and whenever a file watcher sees a change: new directories add agents, edits refresh, deletions retire (history kept). The app has a Team view with a list, an editor (handle, description, model, permission profile, budgets, body with `@` completion), memory viewer, per-agent inbox, and Retire. Agents are assignable and receive notifications. Refine and Integrate buttons are present but disabled until slice 2.

**Milestone 2, slice 2: utility calls and Refine.** `ak-runtime` locates the Claude Code binary (configured path, native installer default, PATH; never the npm `.cmd` shim) and runs tool-less calls: `-p` with the instruction, material via stdin, `--tools ""`, strict MCP config, hooks disabled, replaced system prompt, no session, cwd in a per-call directory under the home dir with the system prompt, input, stdout and stderr kept. The runner is a trait, so tests use a fake. Refine builds its request from the draft and the roster, strips fences from the reply, restores the harness-owned frontmatter keys with warnings, and records every call (proposal, cost, decision) in a `utility_calls` table. A daily global budget check runs before each call. The editor shows a running state, then the proposal as a line diff with Accept and save, Edit first, and Discard. Pending proposals survive closing the editor. Refine on an unsaved new agent saves the draft first. Verified against the real binary on 2026-10-14 (about three cents per call). The CLI binary has its own login, separate from the desktop app; the runner checks `claude auth status` before each call and reports the login hint. Replies that put a bare `: ` inside an unquoted frontmatter value are repaired by the parser, and the prompt asks for a block-scalar description. Live test: `cargo test -p ak-runtime --test live -- --ignored --nocapture`.

**Milestone 2, slice 3: the bridge.** New crate `ak-bridge`: an axum server on an ephemeral loopback port. `POST /mcp/{token}` is a small MCP Streamable HTTP server (JSON responses only, no streams) exposing the board tools as the run's agent: inbox_list, inbox_handle, team_list, ticket_get, ticket_list, ticket_create, ticket_update, ticket_move, ticket_assign, ticket_comment, ticket_reply, memory_read, memory_update, and agent_activate (which reports that direct activation is not available until the scheduler lands). Tickets are addressed by key, columns by name or kind, actors by handle. Mutating a ticket auto-handles the agent's notifications about it. `POST /hooks/{token}/pre-tool-use` evaluates the agent's permission profile in Claude Code's rule syntax (core `permissions` module); uncovered calls become `approvals` rows and the request waits for the human's decision or times out to deny. `POST /hooks/{token}/stop` blocks the stop with a reason while wake notifications are pending. Tool names use underscores, not the dots in design section 9, because they are exposed as `mcp__board__<name>`. The app did not start the bridge until slice 4.

**Milestone 2, slice 4: the supervisor.** New crate `ak-supervisor`. `Supervisor::start_run` spawns Claude Code headless per run (`-p` with the wake prompt, `stream-json` output, a fixed session id, the composed system prompt appended from a file, the bridge's MCP config and hook settings, the profile's permission mode and tool lists, the resolved model, turn and dollar caps) with the API key env removed and the autoupdater off. A driver task parses the stream into `run_events` rows, publishes `RunNotice`s (started, event, ended), enforces the wall clock and a startup timeout, and records exit reason, turns, tokens, cost and the final result on the `runs` row. Each agent works in its own git worktree beside the repository, at `<parent>/<repo-name>-agents/<handle>` on branch `agent/<handle>`, created on first run and reused after. The per-project `Scheduler` wakes agents on wake notifications or on an explicit activation, bounded by global run slots, a per-agent wake rate limit, per-agent and global daily budgets, and a churn guard that puts a repeatedly crashing agent into Cooldown. Stop kills the process and leaves the agent wakeable; Halt kills it and refuses to wake until Resume. The app starts the bridge and supervisor at launch, spawns a scheduler per open project, and shows: a state dot per agent in the Team list, a Pause all / Resume all toggle, Wake now / Stop run / Halt / Resume on the agent, the live transcript of a run in progress, run history with on-demand transcripts, and pending approvals at the top of the Inbox with Approve and Deny (the sidebar badge warns). Settings shows the bridge address. Tested with a fake Claude Code binary (`fake_claude`) that replays scripted stream-json, hangs, crashes or reports an API error.

**Milestone 2, slice 5: one agent completing a ticket end to end.** Verified twice against the real binary on 2026-10-14 with `cargo test -p ak-supervisor --test live -- --ignored --nocapture` (about 45 cents and 105 seconds per run with sonnet). The scheduler wakes `@dev` on the assignment; the agent reads its inbox and the ticket over the bridge, moves the ticket to In progress, branches `ticket/DEM-1` in its worktree, edits and commits with the key in the message, comments, moves the ticket to Review, checks its inbox again, writes memory, and the run ends Completed with cost and token counts recorded. The first run exposed, and the second confirmed fixed: store write transactions used a deferred `BEGIN`, so a tool call upgrading to a write while the run-event writer held the lock got `database is locked` at once (now `BEGIN IMMEDIATE`, which waits); `ToolSearch`, which this Claude Code version calls to load deferred MCP tools, was in no profile (now allowed in both, with `TodoWrite`); a prefix rule such as `Bash(git status*)` matched a whole compound command (rules are now judged per simple command: denied if any part is denied, allowed only if every part is allowed, and command substitution never matches an allow rule); input token counts ignored cached input; and the transcript was cluttered with hook, thinking-token and rate-limit events. Read-only git commands (`show`, `rev-parse`, `merge-base`) are now allowed in both profiles and `git branch` in trusted. The template no longer bakes placeholder text into the description.

**Milestone 2, slice 6: Integrate.** One utility call per chosen target, in parallel under the utility-call cap, plus an optional call for the changed agent itself that rewrites its own `## Team` section from the roster. The request carries the description and ownership lines (the four bold contract lines, read from the files) of every teammate, the full definition of the changed agent and the full definition of the target. The reply is parsed like Refine (fences stripped, harness-owned frontmatter keys restored with warnings) and then checked against the target: a changed description, a changed identity or ownership contract, or any section other than Team that is changed, added or removed becomes a warning on the proposal, never a rejection. Each call is a `utility_calls` row with `target_id`; pending ones load with the authoring agent and survive closing the editor. The Integrate button in the editor opens a picker (every active teammate plus the agent itself, all on by default), then shows progress per target, failures, and one diff per proposal with Accept and save or Discard, plus Accept all and Discard all. Verified against the real binary on 2026-10-14 (about three cents, ten seconds): the model wrote the Team entry and tightened the target's You never line to resolve an overlap, which the review flagged as a warning. Live test: `cargo test -p ak-runtime --test live -- --ignored --nocapture`.

**Milestone 2, slice 7: chats and threads.** Chats are containers (direct with two members, group with a name); every message lives in a thread with a title. Core has the chat model, six chat events, the routing rules from design section 6 (a direct message wakes the other member and informs the human; a group post reaches the thread's participants and wakes them only when the human wrote it; a new group thread is announced without a wake; a mention in a message notifies as everywhere else), and pure commands for creating chats and threads, posting, membership and pausing. Migration 0006 adds chats, members, threads, participants, messages and two FTS5 tables kept in step in the same transaction. Search is scoped to the caller's chats for agents and unscoped for the human. Idle threads are archived by a housekeeping pass on project open and hourly (period per project, default 7 days) and reopen on post. Paused threads reject agent posts, hold what the human posts, and release it on unpause, mirroring freeze. The bridge gains chat_list, chat_direct, chat_create_group, thread_list, thread_search, thread_read, thread_create and thread_post, enforces membership, shows thread context in inbox_list, and posting handles the agent's notifications about the thread; the system prompt tells agents what chats are for. The app has a Chats view: the chat list with New direct and New group, a thread list per chat with New thread and an archived toggle, full-text search, the thread with markdown messages, a compose box with @ completion and Ctrl+Enter, and Pause and Unpause. The inbox opens threads. Not yet exercised with a real agent.

**Milestone 2, slice 8: Export and Import.** `ak-runtime::snapshot` owns the repository's `.agentic/` directory: `agents/<handle>/agent.md` (and `memory.md` when asked) in the same layout as the home directory, plus `policy.toml` with the shared project id. Export writes every current agent, removes snapshot agents no longer on the team, writes the policy by default, leaves memory out by default, and stages with `git add` (never commits, never switches branches). Import review reads a chosen repository's snapshot and classifies each agent as new, changed or identical against the project, reads memory if present, and reports whether the snapshot's policy carries this project's shared id. Apply writes only what was chosen and lets reconciliation pick the files up; an imported policy goes through the same path as the settings screen. Drift compares both sides (changed, only in the repository, not exported yet) on project open, after export and import, whenever the home directory reconciles, and whenever the repository's `.agentic/agents` changes on disk (watched only once it exists, never created unasked). Onboarding: adding a project whose repository already carries a snapshot opens the import review at once. The Team view has Export… (a dialog with the three options) and Import… (a folder picker), a strip naming how many agents differ with a Review… button, and a marker on each drifted agent. The import review lists each agent with its status, a diff for changed ones, an optional memory checkbox, and the policy checkbox (on only for the same project, with a warning otherwise). Never `.claude/agents/`.

**Milestone 2, slice 9: oversight.** Guardrails from design section 12. `ak-core::guardrails` holds the pure rules over a subject's events: ticket ping-pong (moves or reassignments in a window), comment storm (agent comments in a window) and mention loop (a trailing run of agent-to-agent mentions with no progress and no human word in between, on a ticket or a thread). A `GuardrailMonitor` per project evaluates every subject an event burst touches, freezes the ticket or pauses the thread as the system, and records a `guardrail.tripped` event that notifies the human (kind Guardrail, never a wake); frozen tickets and paused threads are left alone, so a trip fires once. The scheduler applies run churn with three strikes (consecutive runs that handled nothing they were woken for) before the cooldown, and records a wake-storm trip at most once an hour when an agent hits its wake rate. The bridge counts identical consecutive tool calls per run and, at the threshold, denies the call and raises an event the scheduler turns into a stop with exit reason GuardrailTripped. Turn, cost and wall-clock budgets end runs as before, through Claude Code's flags and the driver. The Overview view lists every project with running agents, halted agents, approvals waiting, unread inbox, cost today against the global budget, and today's trips, refreshed every few seconds; every registered project is now opened at startup (store, watchers, scheduler, guardrail monitor), so agents wake in all of them and the overview sees all of them. Project settings expose every threshold. The agent editor shows what the agent has cost today.

**Milestone 2, slice 10: hardening (first pass).** A single-instance lock: `~/.agentic-kanban/instance.lock` is held with an OS file lock for the life of the process, so a second AgenticKanban on the same home directory shows a startup error and a crash never leaves a stale lock behind. Crash recovery: when a project is first opened in a session, runs still open in its store are closed as Crashed with an explanatory error and agents stuck in Starting, Running or Stopping return to Idle. Run retention: the hourly housekeeping pass drops the transcripts (run events and run directories) of runs that ended before the global retention period, keeping the run rows for cost history. The Postgres store is deferred until a second machine needs the same project; the trait boundary is in place.

**Visual overhaul: liquid-glass theme.** The whole UI now uses one look in both light and dark, following the system setting: translucent panels and cards with a hairline rim, floating over a soft colour backdrop, with continuous rounding, capsule controls, the iOS system colours and Segoe UI. Colours and frames come from `crates/ak-app/src/theme.rs`, and the shared controls from `widgets.rs`. The sidebar and ticket panel float inset from the window edge, and toasts are capsules. No behaviour changed. Text fields have explicit ids, so a card appearing above one cannot drop its focus.

## Known gaps and deliberate choices

- Dragging a card moves a small ghost label, not the card itself. Cosmetic; egui's built-in drag source broke clicking, so the card uses its own click-and-drag handling.
- Your own actions never reach your inbox. Design, not a bug. The inbox stays empty until a second actor exists.
- Commits go to the private repo `geawilliamsUK/AgenticKanban` on GitHub, branch `main`.
- Agent runs use the user's own Claude Code login, so the user's global settings, hooks, plugins and CLAUDE.md load into every run (the SessionStart hooks add about ten seconds). Isolating that would lose the login, so it stays.
- No real run has been driven from the app window yet. The live test drives the scheduler directly and approves every request itself; the Inbox approval cards, the live transcript and the run controls are built but unexercised by a real run.
- Agents sometimes call a board tool before loading its schema and get a missing-field error; the error now says to read the version from ticket_get, and they recover.
- Every registered project opens at startup, so agents in all of them can wake as soon as the app starts. Pause all in a project's Team view holds that project; the global daily budget holds everything.
- Turn, cost and wall-clock limits end runs without recording a guardrail trip; the run's exit reason is the only record.
- The glass is simulated. egui has no backdrop blur, so the backdrop is a pre-blurred texture and each surface is a translucent fill with a rim and a top highlight. Real refraction would need a custom render pass.
- The default permission profiles were rewritten after the first real team run (2026-10-14): 122 of 129 approval requests were commands prefixed with `cd "<worktree>" &&`, and the rest were pipes to `tail` or `head`, `ls`, `cat`, `mkdir`, `git -c user.name=... commit` and Claude Code's task-list tools. Every part of a compound command must be covered, so the profiles now list the everyday shell verbs, the read-only git commands, cargo and rustup, and Claude Code's bookkeeping tools; trusted adds editing, file management and the git commands that change the worktree's own branches; a third preset, integrator, adds merging. Pushing is never listed, so it always asks; force pushes, hard resets, `git clean` and recursive `rm` are denied. `git -c key=value` and `--no-pager` are ignored when matching, and `2>&1` is a redirection, not an operator.
- Projects have an integration branch setting (default: the repository's default branch). The prompt tells agents to branch from it and to leave their worktree on `agent/<handle>` when they finish, so an integrator agent can merge and delete ticket branches without fighting checkouts.
- The Team view has Stop all runs beside Pause all; Pause all only prevents new runs, which the first team run showed is not what a person reaching for a brake expects.
- The desktop-control tools cannot target the dev build in a session that started before its Start menu shortcut existed. The shortcut is at `%APPDATA%\Microsoft\Windows\Start Menu\Programs\AgenticKanban.lnk`; request access to "AgenticKanban" at the start of a new session.
- Settings view (added 2026-10-14): global handle and display name, Claude Code binary path with a Check that reports version and login, Refine model, concurrency caps, daily budget, run retention; per project: name, Refine model override, agent run model, push policy, project MCP servers. Per-agent model is a picker in the agent editor. Model resolution for Refine: project override, then global, then Claude Code's own default. Global settings are re-read by the backend on save; the runner is rebuilt from them.
